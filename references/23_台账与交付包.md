# 04　台账与交付包

## 1. 总台账：一库一行，字段固定

**建议列（17 列，实测够用且不冗余）**：

| # | 列名 | 说明 |
|---|---|---|
| 1 | 序号 | 连续流水号 |
| 2 | **编号** | 超链接 → 原件（可点击） |
| 3 | 标题（真实题名） | 从**真实索引**提取，**禁止模板文字** |
| 4 | 资料名称（原件文件名） | 实际文件名 |
| 5 | 类别 | 如"原始史料·战后报纸见出全集" |
| 6 | 责任者/机构 | 作者或发布机构 |
| 7 | 馆藏/来源 | 收藏机构 |
| 8 | **获取来源网址** | **在线回溯地址，必填**（用户会检查） |
| 9 | 时段 | 年份或时段 |
| 10 | OCR需求 | 需OCR／无需OCR／不适用 |
| 11 | **文字状态（文字粒度）** | 全文级／要点级／目录级／标题级 |
| 12 | 适用章节 | 对应论文大纲的小节号 |
| 13 | **文字版/全文** | 超链接 → 可检索文本 |
| 14 | **引用格式** | 可直接抄入注释 |
| 15 | 包内相对路径 | 交付包内位置 |
| 16 | 大小(KB) | |
| 17 | **内容提要** | **不得为空** |

### 三条硬指标
```
[ ] 提要为空的行 = 0
[ ] 引用格式列不出现"待补全""按…格式从原文补全"这类占位文字
[ ] 「文字版/全文」列：有全文的必须给链接；无全文的标"（原件影像，未提取）"
```

## 2. 引用格式：**不猜，宁缺勿错**

自动生成引用时最容易出的错是**从正文抽年份**——参考文献密集的段落里，抽到的往往是**引文的年份**。
**实测踩过**：某条本该是 1990 年代，自动抽到 **1885**。

**分级策略**：

| 材料 | 做法 |
|---|---|
| 已人工核过的著录 | 直接用 |
| 期刊论文 | **刊名用白名单**匹配（先扫全库统计真实刊名，再硬编码候选；按长度降序，避免短名抢先匹配） |
| **年/卷/期/页** | **一律标「（年·号·页待核）」**，不写错信息 |
| 学位论文 | 文件名含 `digest` 或正文含"学位论文／论文要約" → 按**学位论文**著录，不要硬套期刊 |
| 一手史料 | 随文注／注释体（**是否进参考文献表须先确认目标单位的规范**；规范未列"档案"类时，**不入表**） |

## 3. 交付包结构（面向人的查阅习惯）

```
交付_<日期>/
├── 00_先读我/           总台账.xlsx｜文档总目录.docx｜交付说明.docx｜目录结构快照.md
├── 01_研究文献/         01a 自藏｜01b 仓储｜01c 全文文本｜01d 索引
├── 02_原始史料/         按库分目录；库内再分「索引与目录」「原件」「OCR全文」「图版」
├── 03_分析文档/         新版_详版｜旧版_暂留
└── 04_项目文件/         项目文档与脚本
```

**两条实现要点**：
1. **用硬链接建副本**（Windows：`os.link`）：**零额外占用**，且在原文件被就地重写时同步更新；
2. **目录名用包内名做排除**（打压缩包时）：`7z -xr!<包内目录名>`——
   ⚠️ **写源盘路径会静默失效**（实测本该 80 MB 的"轻量版"压出 3.4 GB）；
   更稳的做法是**在脚本里生成显式文件清单**交给 7z（`@listfile`），完全确定。

## 4. 压缩包三档（别只做一个）

| 档 | 体积量级 | 含什么 | 用途 |
|---|---|---|---|
| **轻量版** | 数十–百余 MB | **全部文字类**（台账、说明、分析文档、全文文本、索引）+ 各库索引与目录 | 邮件发送 |
| **演示版** | 数百 MB | ＋**研究文献原件 PDF**＋**图版原件**（不含大型影像/扫描件） | 当面演示／U 盘 |
| **完整版** | 数 GB | 全部（含影像原件、扫描件） | 归档 |

## 5. 两个环境坑（会让人以为"清理失败"）

### 5.1 删除不释放空间
某些受管控环境里 `rm` / `Remove-Item` / `os.remove` 都"成功"、文件也消失，
但**磁盘可用空间 0 变化**（被转入回收站）。

**对策**：先**截断**再删——
```python
with open(p, "r+b") as h:
    h.truncate(0)      # ★ 写入操作，真正释放簇
p.unlink()
```
**实测**：两个错误压缩包（3.36 G + 4.55 G）截断后**释放 7.91 GB**；直接 unlink 毫无收益。

### 5.2 批量删除会被拦截
一轮删除超过阈值（实测 50 个文件）会被中止，甚至**杀掉整个进程**。

**对策**：
- **优先"重写"而非"删除"**：例如 md→docx 时把内容**从 stdin 喂给 pandoc**，**零临时文件**；
- 必须删时**分小批**；
- 临时目录**按运行时间戳隔离**，用完不删（比删更省事）。
