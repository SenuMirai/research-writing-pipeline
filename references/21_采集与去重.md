# 01　采集与去重

## 1. 采集时必须同时记录的一件事

每抓完一份产物，**立刻写下**：

```
产物：<文件名>
引用单元：<一条报刊标题 / 一件档案 / 一次会议 / 一张图版>
关系：1:1 还是 1:N
若 1:N → N 大约是多少？
来源是否"按关键词检索"产生？（若是，则必然与其他检索结果重叠）
```

**为什么**：这份记录决定了后面要不要去重、能不能逐条编号。**丢了它，后面全靠猜。**

## 2. 三种典型产物形态

| 形态 | 例 | 引用单元关系 | 对策 |
|---|---|---|---|
| **一档一条** | 口述录音逐条、图版逐张、论文逐篇 | 1:1 | **A 方案**：直接逐条编号，无需去重 |
| **整批导出** | 公报题名全量 JSON、会议录全量 JSON | 1:N（N 大但**不重叠**） | **B 方案**：全集作编号载体＋定位式 |
| **多轮检索** | 报刊库按关键词分批导出（**本次事故**） | 1:N **且互相重叠** | **必须先合并去重**，否则同一单元多个归属 |

## 3. 去重的四步

### 步 1｜选定"引用单元主键"
必须是**能唯一确定一条材料**的字段组合，且**在原始数据里存在**。

- 报刊见出：`(题名, 报纸名, 日期, 朝夕, 版面)`
- 档案目录：`(档号, 件名)` 或 `(全宗号, 案卷号, 件号)`
- 会议记录：`(机构, 日期, 会期, 号次)`
- 论文：`(DOI)` 或 `(作者, 题名, 年)`

⚠️ **不要用"行号"或"文件内序号"**——换一次导出就变。

### 步 2｜归一化（**这一步漏了就会误判重复/漏配**）
- **NFKC 统一全半角**：`unicodedata.normalize("NFKC", s)`
- 去空白（含全角空格 `\u3000`）
- 引号统一（`「」『』""''`→ 去掉或统一）
- 日期统一成 `YYYY-MM-DD`
- ⚠️ 归一化只用于**比对**，**写出的原件保持原样**

### 步 3｜去重并留痕
- 去重后**保留一个"命中来源"列**：该条在几份原始产物里出现过、分别是哪些文件。
  这样**溯源可查、审计可复现**。
- 输出**去重报告**：输入文件数｜输入行数｜去重后条数｜重复率｜去重键｜分卷统计｜抽样 20 条。

### 步 4｜分卷（当全集过大时）
按**时间**（年/十年）或**地域**分卷，便于打开与定位。
分卷后：**引用对象＝所属那一卷**，而不是整个大全集。

```bash
# 一键完成 步2-4
python scripts/dedupe_corpus.py --config config.json --library B
```

## 4. 实测数据（事故案例）

| 指标 | 数值 |
|---|---|
| 原始产物 | 136 份关键词检索 CSV |
| 输入行数 | 28 万余 |
| 去重后 | **17 万余** |
| 重复率 | **38.7%** |
| 分卷 | 66 个年份卷（1946—2011） |

**结论**：**近四成是重复行**。不去重就有近四成材料"有多个家"，任何引用都会指错。

## 5. 采集阶段的三条纪律

1. **先定引用单元，再决定抓法**（能按条抓的，绝不整批抓）。
2. **多轮检索的产物只作"检索留痕"**，不进入引用体系。
3. **抓完立刻做一次 20 条抽样人工核对**——机器去重会犯错，抽样是最便宜的保险。
