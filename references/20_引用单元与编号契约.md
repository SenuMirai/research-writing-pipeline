# 02　引用单元与编号契约

## 1. 编号格式约定

```
<前缀>-<序号>          例：L01、A015、B1234
<前缀>                 例：A（库级锚点，仅用于"谈论整个库"，且正文不写方括号）
<类别>-<序号>          例：索引-03、工具-12、分析-07、全文-215、成果-08、排除-02
```
- **前缀**：一个字母代表一个库（`L` 研究文献、`A/B/C…` 史料库、其余为功能性类别）。**前缀表写在配置里**。
- **序号位数**：按预期规模定（≥1000 条用 4 位）。**定了就不再变**——位数变化会造成排序错乱。
- ⚠️ **不要用文件名当编号**（文件会改名）；**不要用行号**（重跑会变）。

## 2. 两条编号策略（二选一，写进配置）

### A. 逐条编号（引用单元 = 文件单元）
```
规则：每条材料 = 一个文件 = 一个编号
适用：一档一条的库（口述证言、图版、论文）
优点：编号即链接，最稳
```
### B. 共用源编号 + 定位式（引用单元 < 文件单元）
```
规则：一条材料 不单独占编号，而是"共用所属聚合文件的编号"，
      再用【定位式】把它从聚合文件里定位出来
适用：整批导出且不可按条抓的库（公报题名、报纸见出）
定位式举例：报纸＋日期＋朝夕＋版面；期号＋题名；档号＋件名
```
⚠️ **B 方案的两条硬约束**：
1. **聚合文件必须是"去重后的全集"**，不能是"某一次检索的结果"（否则一条会有多个归属）；
2. **定位式必须写在台账与分析文档里**（读者要能据此在全集里找到那一行）。

## 3. 冻结机制（防编号错乱的核心）

```python
# 伪码
old = load(registry)                 # 上次的注册表
for f in files:                      # 固定的排序（按相对路径）
    if f in old: id[f] = old[f]      # ★ 沿用，绝不重排
    else:        id[f] = next_free() # 新文件领新号
```
- **一经分配，永不移位**：在目录中间插入新文件，不让已有编号顺移。
- **删除的编号退休不回收**：避免历史引用歧义。
- **自检**：`python scripts/registry.py --config config.json --check` 连跑两次，
  **已有编号变动数必须为 0**（脚本以退出码表示，非 0 即失败）。

## 4. 编号必须"可点即开原件"

- 正文里的 `[编号]` **一律是超链接**。
- **链接模式二选一**（写进配置 `link_mode`）：
  - `absolute`：`file:///绝对路径` —— 本机用，换机即废；
  - **`portable`：包内相对路径** —— **交付默认用这个**，整包搬到任何盘符/机器都能点。
- 生成时用 `os.path.relpath(目标, 文档所在目录)`，并统一分隔符。

## 5. 「裸编号」定义与门槛（本契约最硬的指标）

**裸编号**＝只写到库级、不指向具体引用单元的编号：
```
❌ [A]        ← 读者点进去只看到整个库
❌ [A12]      ← 若 A12 是一个"聚合文件"，且该句谈论的是库里某一条，则同样是裸编号
✅ [A12-0034] ← 指向具体引用单元
✅ [B-1964]   ← B 方案：指向"1964 年卷"，配合"报纸＋日期＋版面"定位
```
- **门槛：0**。
- **唯一例外**：该句谈论的是**整个库** → **不写方括号**，直接写 `A 库系`。
- 检测：`grep -rP '\[[A-Z]{1,3}\d{0,3}\](?!\()' --include=*.md .` 必须为空。

## 6. 编号契约的验收清单

```
[ ] 配置里每库都写了 citation_unit（引用单元）
[ ] 配置里每库都写了 strategy（A 或 B）
[ ] 配置里每库都写了 level（引用层级）
[ ] B 方案的库：聚合文件是"去重全集"，且有去重报告
[ ] registry 连跑两次，编号变动 = 0
[ ] 正文裸编号 = 0
[ ] 随机抽 3 个编号，点击能打开原件
[ ] 台账「编号」列与注册表一一对应
```
