# 32　与导师／合作者的协作循环

> 这一环处理不好，前面所有工程化都会被"方向被推翻"抵消。

## 1. 接收意见：三步落地

```
① 复述  —— 用自己的话把意见重述一遍，请对方确认（"我理解您的意思是……对吗？"）
② 定域  —— 给出影响范围：这一改动会牵动哪些章、哪些表、哪些编号
③ 回报  —— 改完后给出【改动清单】（改了什么、在哪、为什么这样改），而不是只说"改好了"
```
**为什么必须"复述"**：意见中的模糊词（"太单薄""不够有力"）若不复述，很可能改错方向，
而**改错方向的代价大于晚一天动手**。

## 2. 遇到"意见与材料冲突"怎么办

**绝不做两件事**：① 硬按意见改（违背材料）；② 沉默不改（违背意见）。

**做法：先摆事实，再给选项**
```
【事实】第 X 节现有材料只有 N 条，且都是"标题级"，无法支撑该论断。
【选项 A】补料（需要某库的缩微胶卷，约需 T 时间）
【选项 B】把该节降格合并进上一节，论点改为……
【选项 C】该节改为"研究展望"，不作论证
【我的建议】B，理由是……
```
**导师要的是"可决策的选项"，不是"我做不到"。**

## 3. 结构性变更：**先版本化，再动手**

- 大纲、体例、编号体系这类**结构性变更**：
  1. 先**记录变更前的状态**（版本提交/快照）；
  2. 再执行；
  3. 写**变更说明**（改了什么、为什么、影响哪些已完成的产出）。
- **已完成且被认可的产出不得静默改写**：若必须改，**明确告知并给出改动清单**。

## 4. 与"未来的自己"协作（等同与导师协作）

- **决策日志**：每次做取舍（为什么选 A 不选 B）写一行，注明日期与理由；
- **不可变事实清单**：确认过的日期、人名、数字，集中一处，全篇引用它；
- **未决清单**：待核的事项集中一处，避免散落各处遗忘。

## 5. 交接（把项目交给别人／半年后的自己）

**三件套**：
```
00_先读我/   总台账（每条带编号+链接）｜文档总目录｜说明文档
体例执行版    （一张表，写清字数与著录细节）
自检报告      （编号冻结/去重/链接 三项的结果留痕）
```
**判据**：**对方只拿这三件，能否自己跑一遍自检、并独立核验任意一条引用？** 能，才算可交接。

## 6. 沟通频率与颗粒度（经验值）

| 情形 | 建议 |
|---|---|
| 结构性方案（选题、大纲、章节划分） | **多版本提案**，一次给 2–3 版并附取舍理由 |
| 单章写法 | 先给**一节样章**，确认体例后再批量生产 |
| 细节纠错 | 攒成**一批**一起报（避免碎片化打扰） |
| 发现自己出错 | **立即主动报**，附根因与影响范围，不等对方发现 |

> **最后一条尤其重要**：把"被发现的错误"变成"主动报告的错误"，
> 是长期协作中信任积累最快的方式，也是本技能 `25_复盘案例` 那一节存在的原因。
