# 12　检索与获取

## 1. 三类入口

| 类型 | 特征 | 优点 | 陷阱 |
|---|---|---|---|
| **机构库／仓储**（大学、学会、档案馆） | 有 API 或规整检索页 | 可编程、可复现、元数据全 | 分页与会话；文件名编码 |
| **档案／公文目录与全文库** | 表单检索（常为 ASP.NET/JSP 会话式） | 一手材料的唯一来源 | **必须带会话与隐藏字段**；导出可能是"按关键词整批" |
| **学术检索／引文库** | 元数据 + 引用网络 | 用"被引/参考文献"迅速锁定关键文献 | 常无全文，需回机构库取 |

**推荐路径**：学术检索**定位** → 机构库**取全文** → 档案库**取一手材料**。

## 2. 采集技法（按站点形态）

### 2.1 表单检索型（有会话/隐藏字段）
```
① GET 检索页 → 抓隐藏字段（如 __VIEWSTATE / _csrf / ViewStateGenerator）
② POST 检索参数 + 隐藏字段（带上同一 Cookie 会话）
③ 解析结果行：编号、题名、日期、分类、详情链接、缩略图
④ 逐条取详情页补全字段
```
**注意**：
- 抓取的**字段名可能是全角或用 `$` 分隔**——按原样使用，不要"美化"；
- 某些站点**只接受特定按钮名**（试错时要保留原始 value，含全角空格）；
- **慢**：详情页逐条取，上万条要有分批与断点。

### 2.2 API／JSON 型
直接取 JSON，最省事。注意分页参数与总量上限。

### 2.3 批量导出型（CSV/Excel）
- **注意编码**（`旧编码`/`GB18030` / `GB18030` / `EUC-KR` / `UTF-8-BOM` 都可能）——按 utf-8 硬解会得到乱码；
- **导出常按"检索条件"生成** → 多次不同关键词的导出**必然互相重叠** → 必须去重（见 `21_采集与去重.md`）。

### 2.4 图像／影像型
- 检查**是否有更高清晰度档位**（把 `/small/` 换成 `/xlarge/` 之类常有效）；
- 记录**图片直链与详情页 URL**（两者都要，前者作图版，后者溯源）。

## 3. 采集时**必须同时记录**的四项

```
[ ] 在线来源 URL      （溯源；每一条都要有）
[ ] 授权与可引用性    （如"刊载无需申请，只需标注馆藏"／"需申请"／"仅限阅览"）
[ ] 引用层级          （全文级/要点级/目录级/标题级）
[ ] 产物与引用单元的关系（1:1 → 逐条编号；1:N → 先去重建全集）
```

**为什么第 2 项至关重要**：
很多机构明确写了授权口径（例："本馆所藏图像用于出版物无需申请，只需标注出处"）。
**不记下来，到写作时不敢用或重复求证，白耗时间；记错了，会构成侵权。**

## 4. 网络可达性与取全文

| 情形 | 对策 |
|---|---|
| 站点直连失败 | 换网络；或**用服务端抓取**（WebFetch 类工具走服务端出口） |
| 代码托管/仓库被阻断 | 用镜像代理（如 `ghproxy` 系） |
| 大文件站点限速 | 后台长跑 + 断点续传；**估工时再决定是否值得下** |
| 需要人工登录/验证 | **不要绕**；走馆际互借或线下调阅，并记入"需人工获取"清单 |

## 5. 全文获取的优先级（省时间）

```
1) 开放获取全文（机构库/作者主页）
2) 可直取文字层的 PDF（先测：抽一页看有没有文字）
3) 有文字层的 EPUB/HTML
4) 扫描件 → 按被引篇目做**精准 OCR**（不要整库 OCR）
5) 只借阅 → 记"需人工获取"，并标注引用时须回原件
```

## 6. 阶段 2 的交付物

```
[ ] 原件（按来源库分目录存放，不重命名）
[ ] 采集留档（脚本/参数/时间；换机可复现）
[ ] 元数据索引（JSON/CSV：编号、题名、日期、URL、层级、授权）
[ ] 需人工获取清单
[ ] 明确标注"本次未取得"的条目（诚实交代缺口）
```
